# 代码审查

对一批代码改动做质量审查，产出**分级问题 + 结论**。**审查、不代改**——只出报告，修复由 owner 按报告处理。

## 输入

- **改动范围**：默认当前未提交改动（`git diff` / `git diff --staged`）或指定的一批文件；
- **需求依据**：`功能清单.md` 对应功能的要求与完成标准（改动最终要满足的产品目标）；
- **设计依据**：`技术方案.md` 对应功能/CHG 的改动设计（改成什么样才算对）；
- **规范**：涉及 L3 域 `l3Knowledge/coding-conventions.md` + `gotchas.md`、对应端 `knowledgeBase/coding-conventions/{端}.md`（域内优先 > 通用端）；
- 涉 UI 则 `ui-specs/*`、涉平台则 `infra-knowledge` 对应文档。

## 开审前必做：先读齐规范，再审代码

**不许跳过、不许凭记忆审**。开审第一步先把下面读进来，读不到要在报告里说明（不是默默略过）：

1. **定域定端**：从改动文件路径定位所属 L3 域与端（Java 服务端 / Android / iOS / RN / 小程序 / H5）。
2. **读域内规范**：该域 `l3Knowledge/coding-conventions.md` + `gotchas.md`（**没有才降级到通用端**）。
3. **读通用端规范**：`knowledgeBase/coding-conventions/{端}.md`。
4. **多域/多端改动**：每个涉及的域/端都按上面各读一遍，别只读一个就动手。

> **域内优先 > 通用端**：两者冲突时以域内为准。**没读规范就出的 review 结论无效**。

## 审查维度（对照，不凭感觉）

| 维度 | 看什么 |
|---|---|
| **需求满足** | 改动是否满足 `功能清单.md` 对应功能的要求与完成标准，有无漏做/跑偏（不只是"照方案改了"，还要"改对了功能想要的"）|
| **设计一致** | 改动是否落实技术方案的改动设计（方法/接口/数据结构/调用关系），有无偏离或缺漏 |
| **规范符合** | 命名/分层/事务/日志等符合域内 + 通用端规范；命中的 `gotchas` 坑已规避 |
| **边界与健壮** | 空值/异常/并发/回滚/降级/边界值处理；错误吞掉、裸 catch、资源未释放 |
| **单测质量** | 覆盖正常+异常+边界；外部依赖（DB/Apollo/RPC/运营中台/AB/静态类/日志）**已 mock**、无真实连接 |
| **改动边界** | 只改了任务/CHG 范围内的文件，无越界改动、无顺手重构 |
| **残留** | 无 `TODO`/`FIXME`/调试打印/注释掉的死代码/硬编码魔法值/敏感信息（密钥/token） |
| **实验灰度** | 涉分流未自编算法（hashCode%N 等），用了统一实验能力 |
| **性能** | 无 N+1 查询、循环内无多余 IO、大数据量有分页/分批（一般 P2，明显劣化到影响可用性算 P1）|

## 核心纪律

0. **先读规范再审**（见「开审前必做」）：域内 `coding-conventions.md`+`gotchas.md` 与通用端 `coding-conventions/{端}.md` 必须先读进来；没读就审 = 无效结论。报告结论块须注明本次读了哪些规范文件。
1. **证据导向**：每条问题必指 `文件:行` + 一句为什么、给修改方向；指不出位置的不写。
2. **分级客观**：
   - **P0**：会导致功能错/线上事故/数据错/安全漏洞（如未 mock 真连库、分流自编算法、空指针必现、敏感信息硬编码）
   - **P1**：未满足功能要求/完成标准、偏离技术方案设计意图、踩了未规避的 gotchas、缺关键边界处理、单测缺异常/边界 case
   - **P2**：规范/风格/可读性/次要重复——建议但不拦截
3. **审查不代改**：只出报告，不动代码（改由 owner 按报告处理）。
4. **不评"覆盖是否充分"式空话**：结论要能落到具体条目。

## 结论

- **passed**：无 P0/P1（P2 可留作建议）
- **failed**：存在任一 P0/P1 —— 列出必须先修的项

## 产物（报告）

```markdown
# 代码审查 - {范围：T0X / 需求名}
结论：passed / failed（P0={a} P1={b} P2={c}）
已读规范：{域内 coding-conventions/gotchas 路径}、{通用端 coding-conventions/{端}.md}（读不到的注明）

## P0（必修，拦截）
- [文件:行] {问题} → {修改方向}
## P1（必修，拦截）
- [文件:行] {问题} → {修改方向}
## P2（建议）
- [文件:行] {问题} → {建议}
```
