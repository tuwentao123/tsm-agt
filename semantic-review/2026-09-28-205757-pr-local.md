# 项目画像闭环的定向修复完成，但 CLI 与真实画像补证仍未闭合

上一轮的长文件 coverage、超过 8 个 source refs、重复 profile revision 三项已关闭；P3 的 SDK/Web 双源冲突与已绑定画像的 pending 展示也已修复。当前仍有两个 P2 高严重度缺陷和两个 P3 中严重度缺口。Watch for: **confirmed** — 生产画像 source ref 无法被 audit 读取；**confirmed** — CLI 可在没有 audit 事件时把任务标记为 `SUCCEEDED`；**confirmed** — 首次刷新 pending 被投影为 false；**confirmed** — CLI 不输出 P3 生命周期状态。

**Verdict**: NEEDS_CHANGES

## High-level view

长文件补证现在携带 coverage，否定结论不能用不完整 excerpt 获得 `PASS`。超过 8 个冲突 refs 时剩余 ref 会保持 `NEEDS_EVIDENCE`；同 fingerprint 的第二个画像 job 也不再推进 revision。

画像构建器把 onboarding inventory 的复合摘要写入 `ProfileSourceRef.content_hash`，audit collector 却按纯文件内容 SHA-256 校验。两种 hash 对未变化文件也不相等，真实画像交叉补证读取不到源码。

SDK 已用 profile store 的实时状态覆盖事件投影，Web 也展示 `section_count` 与 `pending_refresh`。但 binding 尚不存在时状态查询固定返回 `pending_refresh=false`；one-shot CLI 既不消费统一状态，也不输出画像、审查和自动停止原因。

one-shot CLI 的 legacy completion 路径在确定性验收通过后直接进入 `FINALIZING/SUCCEEDED`。即使 production composition 注册了 Completion Audit，CLI 也不会调用它。

<details>
<summary>Issues (4)</summary>

1. **画像 source hash 无法用于 audit（confirmed）** — profile 使用“路径+大小+内容”的复合摘要，collector 使用纯内容 hash，导致真实 source refs 全部校验失败；应统一 hash 契约或区分两类摘要。
2. **one-shot CLI 绕过 Completion Audit（confirmed）** — CLI 可在零 audit 事件时将任务标记为 `SUCCEEDED`；应复用 SDK 完成编排或抽取唯一 finalization 服务。
3. **首次刷新 pending 被隐藏（confirmed）** — 无 binding 时 runtime 固定返回 `pending_refresh=false`，即使 store 已有 job；应按 Task workspace/subject 查询 pending。
4. **CLI 缺少 P3 生命周期输出（confirmed）** — CLI 不展示 profile、audit、source refs 和自动停止原因；应消费统一 `RuntimeTaskResult` 字段。

## 画像 source hash 与 audit 内容 hash 不兼容

**高严重度，confirmed。** `ProjectOnboardingScanner.inventory()` 的 source 摘要包含相对路径、文件大小和内容，`ProjectProfileBuilder` 将它原样写入 `ProfileSourceRef.content_hash`。`collect_completion_audit_evidence()` 则用纯内容 `file_sha256(path)` 比较，因此文件未修改时也会静默跳过。

最小复现从当前工作区画像选取 `pyproject.toml`：profile hash 为 `68fd...1db8`，纯内容 hash 为 `b8b0...1769`，collector 返回 `evidence_count=0`。否定结论遇到画像候选后只能耗尽 evidence pass 并进入 `NEEDS_REVIEW`。应统一 hash 算法，或显式区分 inventory fingerprint 与内容 hash。

来源：`src/tsm_agt/core/onboarding.py:286-295`，`src/tsm_agt/core/project_profile.py:228-260`，`src/tsm_agt/core/kernel.py:9912-9933`。

## one-shot CLI 在确定性验收后跳过 Completion Audit

**高严重度，confirmed。** `_finalize_standalone_agent_result()` 在 `LEGACY_GATE` 下验收通过后直接迁移到 `FINALIZING/SUCCEEDED`，调用链中没有 `run_completion_audit()`。production engineering composition 已注册审查端口，这不是 feature-disabled fallback。

注册 `RuleBasedCompletionAuditor` 后执行 one-shot finalizer，结果仍为 `state=SUCCEEDED`、`audit_events=[]`。应让 CLI 复用 SDK 完成编排，或抽取唯一的 verification/audit/finalization 服务。

来源：`src/tsm_agt/cli.py:567-625`，`src/tsm_agt/sdk/runtime.py:1275-1368`，`src/tsm_agt/bootstrap/composition.py:1103-1115,1305-1317`。

## 首次画像刷新被展示为没有 pending

**中严重度，confirmed。** `get_project_profile_status()` 在没有 `project_profile_binding` 时固定返回 `pending_refresh=false`，未按 Task workspace/subject 查询 store。首次 onboarding 会处于“尚无 binding、已有后台 job”的状态。

最小复现中 `store.has_pending_refresh(...)` 为 `True`，runtime status 却为 `MISSING/pending_refresh=false`。应继续查询 pending，只将 revision 和 section count 保持为空。

来源：`src/tsm_agt/core/kernel.py:6119-6140,6741-6752`。

## CLI 没有输出 P3 生命周期字段

**中严重度，confirmed。** SPEC 要求 CLI/Web 展示 profile freshness/revision、audit verdict/source refs 和自动停止原因。`_print_standalone_protocol_status()` 只输出执行状态、领域检查、模型结论和引用校验；CLI 中没有其它相关展示路径。

应让 CLI 消费与 Web 相同的 `RuntimeTaskResult`，而不是直接读取未规范化的 `TaskRuntimeProjector`。

来源：`项目画像与任务完成可信闭环实施SPEC.md:824-860`，`src/tsm_agt/cli.py:628-665`。

## 上一轮四项关闭验证

长文件 coverage 的 `complete=false` 会阻止模型 `PASS`；第 9 个未读 ref 会保留 `NEEDS_EVIDENCE`；stale replacement 与 mutation job 对同一输入只生成一个新 revision。SDK/Web 已消除历史 refresh 事件与实时 store 的双源冲突，并展示已绑定画像的 pending/section count；首次未绑定画像的 pending 缺口是本轮新增问题。

定向 7 个测试文件为 `32 passed`。完整测试为 `1215 passed, 8 skipped, 11 failed`；完整套件未绿，未确认属于 P0-P3 高/中严重度行为的问题没有列入本报告。
