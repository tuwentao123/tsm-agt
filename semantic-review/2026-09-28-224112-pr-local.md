# STALE 项目画像仍可放行“未实现 Web 前端”

完成审查已能对已读画像 source 的完整性进行门禁，也会在审查器未配置时转入 `NEEDS_REVIEW`。但“当前项目未实现 Web 前端”不被识别为否定结论；当 `src/tsm_agt/web/app.py` 的候选已经补读完整、而 Task 绑定画像已是 `STALE` 时，两种审查器都会接受 `PASS`。SDK 与 standalone CLI 只检查 `PASS + evidence_refs`，会继续把该结果迁移到 `SUCCEEDED`。Watch for: **confirmed** — 非 `FRESH` 画像不得接受否定结论的 P2 硬约束可被“未实现”这类同义措辞绕过。

**Verdict**: NEEDS_CHANGES

## High-level view

P1 已将内嵌 Web UI 建模为带 source ref 的入口候选，P2 的补证 gate 也会拒绝未读或不完整的候选；缺口在于是否启用 freshness gate 仍由有限的自由文本词表决定。`未实现` 不在该词表中，Kernel 不会把该回答当作 absence claim，审查器在 source 已完整补读后便允许 `PASS`。两个终结路径没有额外的 claim/freshness 校验，因此同一个审查误判会稳定地成为成功状态。

## 词面否定识别没有覆盖“未实现”

**高严重度，confirmed。** `src/tsm_agt/core/kernel.py` 和 `src/tsm_agt/adapters/completion_audit.py` 分别维护相同的有限 marker 集合，只识别“没有 / 不存在 / 未找到 / not exist / does not exist / no ”。`当前项目未实现 Web 前端` 不命中任一 marker，因此 Kernel 不会将已绑定 revision 的全部画像 section 作为 absence conflict 传给审查器，`_preflight()` 也不会执行 `profile_freshness != "FRESH"` 的 fail-closed 分支。

这不是画像无法定位 Web UI：`ProjectProfileBuilder` 对真实 `src/tsm_agt/web/app.py` 生成包含 `FastAPI`、`HTMLResponse`、`INDEX_HTML`、`<textarea` 和 `<button` 的 source-linked entrypoint 候选；`ProjectProfileContextResolver` 在目标词项无法命中时仍回退保留 entrypoint candidate。未读或不完整 source 会被 `_profile_evidence_gate()` / `_parse_model_verdict()` 拒绝，但 source 已完整补读后，二者都不再有 freshness 约束可执行。

最小复现构造 `profile_freshness="STALE"`、指向 `src/tsm_agt/web/app.py` 的 `ENTRYPOINT` section，以及 `complete=True` 的 `AuditSourceEvidence`。Worker answer 为“当前项目未实现 Web 前端”，审查模型返回带 `event:3` 的 `PASS`：`ModelCompletionAuditor` 输出 `PASS`，`RuleBasedCompletionAuditor` 也输出 `PASS`。随后 `src/tsm_agt/sdk/runtime.py:1290-1321` 与 `src/tsm_agt/cli.py:630-646` 仅以 `PASS` 和 non-empty `evidence_refs` 为条件迁移 `FINALIZING → SUCCEEDED`，不会重新校验 freshness 或 Worker 的否定语义。

应由 Worker conclusion protocol 产出受校验的 `asserts_absence`/claim kind，而非由多个组件重复猜测自然语言。至少应把“未实现、无、缺失、未提供、not found、absent”等同义表达集中到一个保守识别器，并让识别失败但 profile 含相关候选的完成结论转为 `NEEDS_EVIDENCE` 或 `UNDECIDABLE`。回归测试需覆盖 Model 和 Rule auditor、SDK 及 standalone CLI 的完整终结链：`FRESH`/`STALE`/`MISSING` 三种画像状态下，未读、截断和完整补证都不得使任何 absence claim 进入 `SUCCEEDED`。
