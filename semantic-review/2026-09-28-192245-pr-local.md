# 项目画像与任务完成可信闭环仍可被弱事实绕过

改动建立了证据分级、画像持久作业、独立审查和 SDK/Web 投影，但多个关键判定仍由弱事实触发：重复工具调用被算作 continuation 新进展，只校验 hash 的文件读取被算作已审查源码，完成审查又只查看画像固定前 16 段。P1 作业与 Session binding 不能在 revision 变化后收敛，P3 也未如实展示 dirty profile、停止原因和审查来源。Watch for: **confirmed** — continuation fingerprint 无法熔断重复动作；**confirmed** — 否定结论可在审查器未获得源码内容时 PASS；**confirmed** — 相关画像 section 可能不进入审查上下文。

**Verdict**: NEEDS_CHANGES

## High-level view

P0 的 continuation fingerprint 使用全部执行记录及完整 ToolResult；相同动作每重试一次都会增加元素或新的 call id，状态 hash 持续变化。搜索多样化在单文件达到 5 条上限后静默停止，却仍可能报告 `coverage.complete=true`。

P1 已接入 SQLite revision、lease 和后台 worker，但失效 fingerprint 作业会反复 reschedule；Session 画像 binding 又是 write-once，后续 Task 使用新 revision 时 Session 仍声明旧 revision。

P2 使用新的两消息模型 turn并排除 Worker working memory。补证阶段却只核对文件 hash 后标记 source ref 已读，审查模型没有得到任何新源码事实；审查输入还截取画像前 16 段，没有按任务选择相关 section。

P3 可显示 revision、freshness 和 audit verdict，但 workspace mutation 后仍显示 FRESH。SDK 缺少 `pending_refresh`、`section_count`，Web 也不展示 continuation 熔断原因或实际审查读取的 source refs。

<summary>Issues (7)</summary>

1. **重复动作绕过 continuation 熔断（高，confirmed）** — fingerprint 使用带重复项和 call id 的完整执行列表，相同动作每轮都会制造“新进展”；应改为去重的规范 action 集合，并保留未尝试候选判断。
2. **审查补证未产生源码事实（高，confirmed）** — Runtime 只校验文件 hash 就把 ref 标为已读，审查器看不到内容仍可 PASS；应向隔离审查输入提供受限源码片段或结构化观察。
3. **画像固定切片漏掉相关模块（高，confirmed）** — audit 只取 `profile.sections[:16]`，第 17 段后的冲突候选无法阻止否定结论；应按 TaskSpec、goal 和结论实体查询相关 section。
4. **per-file cap 伪报完整覆盖（中，confirmed）** — 单文件丢弃第 6 条后的命中却返回 `coverage.complete=true`；应将 per-file 截断计入 partial coverage。
5. **失效画像作业永久重调度（中，confirmed）** — 旧 target fingerprint 作业不会更新或结束，会被 worker 周期性重复领取；应 supersede 旧作业或原子替换为最新 target。
6. **Session 与 Task 画像 revision 分叉（中，confirmed）** — Session binding write-once，后续 Task 可使用新 revision 而 Session 仍停在旧 revision；应在新 Task 边界推进 Session capsule。
7. **P3 状态误报且缺字段（中，confirmed）** — mutation 后仍显示 FRESH，SDK/Web 缺 pending refresh、section count、停止原因及实际审查 source refs；应从持久 dirty/job/source-read 事实统一投影。

## 重复工具调用持续改变 continuation fingerprint

**高严重度，confirmed。** `Kernel._evaluate_completion_readiness()` 将 `task.tool_executions.values()` 中每条执行放进 `tried_actions`，签名还包含 `execution.result.to_data()`。相同工具名和参数的新调用仍会新增列表元素，ToolResult 的 `call_id` 通常也不同，canonical hash 因此每轮变化。`RuleBasedCompletionReadinessPolicy` 只有在新旧 fingerprint 相等时才返回 `EXHAUSTED`，所以重复同一动作会持续被当成新事实，直到硬预算耗尽。

实现也没有 Spec 的 `has_untried_candidate_action` 分支。应将 attempted action 规范化为去重集合，并在相同事实状态下单独判断 candidate action 是否尚未尝试。

来源：`src/tsm_agt/core/kernel.py:8374-8395`，`src/tsm_agt/adapters/rule_based_completion_readiness/policy.py:96-121`。

## 审查补证只验证文件未变，没有审查文件内容

**高严重度，confirmed。** `collect_completion_audit_evidence()` 调用 `path.read_bytes()` 后丢弃返回值，仅比较文件 hash，并把原 `ProfileSourceRef` 放入 `audit_read_refs`。下一轮 `_preflight()` 把该 ref 视为已处理；`RuleBasedCompletionAuditor` 随即 PASS，`ModelCompletionAuditor` 收到的也只有路径/hash 与“已读”标记，没有源码正文、结构化观察或新的 evidence。现有测试把“加入 ref 后直接 PASS”固化为期望。

“没有接口实现”等否定结论因此可在源码仍包含实现时被接受。补证必须在只读审查边界形成受限源码片段或结构化事实；文件与画像 hash 一致只证明冲突候选仍存在，不能解除冲突。

来源：`src/tsm_agt/core/kernel.py:9848-9885`，`src/tsm_agt/adapters/completion_audit.py:165-190,252-263`，`tests/test_completion_audit.py:36-51`。

## 固定前 16 个画像 section 使相关模块逃逸交叉验证

**高严重度，confirmed。** `run_completion_audit()` 对绑定 revision 只取 `profile.sections[:16]`，没有按 goal 或否定结论查询相关画像。`ProjectProfileBuilder` 先添加聚合段、入口段，再添加按名称排序的模块段；大型仓库的目标模块很容易排在第 17 段以后。其 source ref 不会进入 `_unread_conflicting_profile_refs()`，审查器无法发现与“实现不存在”冲突的候选。

应按 TaskSpec 显式路径、goal 词项和否定结论实体查询绑定 revision，再限制相关候选数量，而不是截断存储顺序。

来源：`src/tsm_agt/core/kernel.py:9901-9911`，`src/tsm_agt/core/project_profile.py:190-233`，`src/tsm_agt/core/project_profile_context.py:39-68`。

## 单文件匹配上限被错误报告为完整覆盖

**中严重度，confirmed。** `_search_text()` 在一个文件达到 `_MAX_MATCHES_PER_FILE = 5` 后直接停止该文件，但只在全局 `len(matches) >= max_matches` 时设置 `truncated=True`。最小复现中，含 20 个 `hit` 的文件在 `max_matches=500` 下返回 5 条，同时给出 `truncated=False`、`coverage.complete=True`、`stop_reason=complete`。依赖 coverage 的排除性判断会建立在错误元数据上。

应记录 per-file truncation，并把整体 coverage 标为 partial，或分别表达“每文件采样”和“全局扫描完成”。

来源：`src/tsm_agt/adapters/builtin/core_tools.py:585-629`。

## 旧 fingerprint 作业会永久 reschedule

**中严重度，confirmed。** `run_once()` 发现当前 identity/discovery 与 job target 不同后，只延迟同一个 job，不更新 target，也不将其标记 superseded。Task mutation 的空 target 作业构建新 revision 后，Task settled 产生的旧 target 作业会在每个 debounce 周期重新 claim、比较并 reschedule。最小复现得到一次成功刷新后连续两次 `run_once=False`，profile revision 停在 2，旧作业持续存在。

应原子更新/替换失效作业的 target，或完成旧作业并 enqueue 去重后的最新目标。

来源：`src/tsm_agt/adapters/local_profile_scheduler.py:91-117`，`src/tsm_agt/adapters/sqlite/project_profile.py:92-151,201-219`。

## Session binding 与后续 Task revision 分叉

**中严重度，confirmed。** `SessionSnapshot.with_project_profile_binding()` 在已有 binding 时无条件返回自身，而 `_bind_task_profile_if_matching()` 始终从 store 的 current profile 给新 Task 绑定。复现同一 Session 三个 Task：第二个 Task 为 r1，刷新后第三个 Task 为 r2，但 Session 仍为 r1。项目上下文当前绕过 Session、直接读 Task binding；Session capsule 不再是 Task 的来源，SDK/恢复若读取 Session binding 会看到错误 revision。

应在新 Task 边界将 Session capsule 推进到本次选定的稳定 revision，同时保持已启动 Task binding 不变；否则应移除 Session binding 的权威含义。

来源：`src/tsm_agt/core/session.py:209-219`，`src/tsm_agt/core/kernel.py:6159-6206`。

## P3 对 dirty profile 和审查来源的展示不完整

**中严重度，confirmed。** `_project_profile_data()` 只比较 Task binding 与最后一次 onboarding snapshot；workspace mutation 仅通知 scheduler，不更新 Task dirty 状态，因此修改源码后仍投影 `FRESH`。投影也缺少 Spec 的 `pending_refresh`、`section_count`。Completion audit 投影忽略 `completion.audit_source_read`，Web 只显示 audit state/verdict；第二轮 audit 的空 `requested_read_refs` 还会覆盖首轮请求。Web 没有消费 SDK 已暴露的 `completion_diagnostics.reason`，fingerprint 停止不会显示“没有新的项目事实或可执行动作”。

应持久并投影 profile dirty/pending 状态和 section count，聚合审查 source-read 事件，并在 Web 映射 `required_work_stalled_without_new_facts` 等 reason。

来源：`src/tsm_agt/core/task_runtime_projection.py:187-249`，`src/tsm_agt/sdk/runtime.py:98-135,875-891,1446-1453`，`src/tsm_agt/web/app.py:1212-1240,1562-1591`。

## 验证覆盖

定向执行 10 个 P0–P3 测试文件，结果为 37 passed、12 subtests passed；`uv run python -m compileall -q src/tsm_agt` 通过。未测试：重复同签名动作的 fingerprint 熔断；per-file cap 标记 partial；同 Session 跨 revision 一致性；失效 job 收敛；审查模型获得可判断的 source 事实；画像第 17 段后的冲突候选；mutation 后 freshness/pending 状态；Web 停止原因与审查 source refs。
