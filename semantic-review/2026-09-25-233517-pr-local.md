# V3 结论协议与最终回答提交

这组未提交改动新增了结构化 `AssistantConclusion`、事实引用校验、最终 Task/Session 联合提交，以及 SDK/CLI/Web 的并列展示字段。SQLite v1→v2 会解除“一个 Session/Task 只能有一条命令回执”的旧约束，同时保留既有 `command_id` 回执。主要问题不在 Projector/Web 的文本推断：这些层当前只读取明确的事件字段；问题在于 `AGENT_DECIDES` 运行模式仍让 Runtime 生成业务恢复/续做指令，且结论协议没有被实际请求或提示模型产出。Watch for: **confirmed**，`AGENT_DECIDES` 下的恢复计划仍会主导下一轮模型行动；**confirmed**，流式响应在受控块非法时会向用户补发协议标签；**likely**，为旧约束保留的非原子回退会重新打开最终回答双写窗口。

**Verdict**: NEEDS_CHANGES

## High-level view

最终回答的正常路径已经将 `llm.completed`、结论校验、`turn.completed` 与 `session.task_result_recorded` 交由 `commit_session_and_task()` 一次提交，并使用稳定的内容哈希 `command_id` 重放。SQLite 的 v1 迁移也会复制历史回执后取消 `(session_id, task_id)` 唯一约束，因此标准升级路径可以保留回执并允许后续最终回答。

不过 `CompletionReadinessMode.AGENT_DECIDES` 只撤销了最后的完成门控。循环前仍根据业务缺口、可恢复工具失败和容量预算生成“选择合法恢复动作”“保留容量完成必需工作”等指令；这不是执行事实或结构诊断，仍是 Runtime 代替模型制定业务 recovery plan。

结论解析会避免把自然语言“已验证”升级为结构化结论，Session、TaskRuntimeProjector 与 Web 也都消费持久化的结构字段而非助手正文。但模型请求没有声明原生结论 schema，也没有注入受控块协议，`REQUIRE_STRUCTURED` 没有进入 Kernel 请求；该能力目前是被动接收而非可实际协商的输出协议。

## AGENT_DECIDES 的 recovery 仍由 Runtime 选择

`src/tsm_agt/core/kernel.py` 的 `_continue_agent_turn()` 无条件调用 `_completion_readiness_gaps()`，从任务验收标准、未完成计划步骤和 post-mutation 检查构造“required work”。随后它无条件计算 `recoverable_required_work` 与 `structured_recovery`，并在 `_latest_recoverable_tool_batch()` 存在结果时把 `recovery_action` 编排为模型指令：“Choose a legal recovery action or an alternative tool”；在容量接近阈值时又要求模型使用特定 effect 完成剩余工作。`AGENT_DECIDES` 仅在最终响应后把 readiness 覆盖为 `diagnostic_only`，没有隔离这些前置分支。

这会使运行时基于业务缺口决定继续、恢复方式和资源分配，即使最终状态不再由 readiness gate 改写。问题不是安全边界中的未知结果暂停或工具幂等保护，而是普通可恢复失败和验收缺口被转换成下一步业务动作。应只在 `LEGACY_GATE` 保留这些分支；新模式可持久化 `completion.readiness_evaluated`，并把不可行动的事实诊断作为上下文交给模型自行决定。

## Provider 声明了结构化结论能力，却没有请求它

`src/tsm_agt/ports/model.py` 提供了 `ConclusionProtocolMode.REQUIRE_STRUCTURED`，而 `OpenAICompatibleModelProvider` 声明 `structured_conclusion=True`。但 `src/tsm_agt/core/kernel.py` 构造 `ModelRequest` 时从不传递该模式，因而始终使用 `OBSERVE` 默认值；`OpenAICompatibleModelProvider._build_payload()` 也只生成普通 Chat Completions messages、tools 与 token 参数，未给出 `conclusion` 字段的 JSON schema、response format 或受控块生成指令。

因此 native `delta.conclusion`/`message.conclusion` 与 `<tsm-conclusion-v1>` 只是适配器被动容忍的私有输入。真实兼容 Provider 不会因为这个请求自动返回任一格式，`require_structured` 也无法使缺失结论失败或降级。应将协议模式作为 Kernel 依赖/配置向每个请求传递，并在 Provider 能力对应的请求体或系统提示中声明唯一的输出通道；不支持时应降级能力声明而不是静默标记为结构化支持。

## 旧约束兼容回退重新打开最终回答双写窗口

`src/tsm_agt/core/kernel.py` 的 `_commit_final_agent_result()` 在收到旧 `session_task_commands(session_id, task_id)` 唯一约束错误时，改为先 `commit(RuntimeUnitOfWork(...))` 再 `commit_session(session_unit)`。两次提交之间进程退出、磁盘错误或并发中断，会留下用户可见答案已在 Task 事件中出现、Session 历史却没有 `session.task_result_recorded` 的状态。SQLite 的 `_migrate_session_task_commands_v1_to_v2()` 应使健康的 v1 数据库不再命中此分支，且新增测试验证历史回执被保留；但保留该 fallback 正是在迁移未生效或旧 store 仍存在时放弃原子保证。应让迁移/兼容失败整体失败，而不是以双写继续。

## 流式非法结论块在完成时泄漏协议文本

`src/tsm_agt/adapters/openai_compatible/model.py` 的 `_stream_complete_once()` 在看到 `<tsm-conclusion-v1>` 起始标记后停止即时转发其后的内容，这对完整合法块有效。完成时它调用 `_normalize_response()`；而 `_extract_conclusion()` 对重复标记、缺少闭合标记、JSON/schema 非法或后缀文本都会返回原始 `text`。接着 `_stream_complete_once()` 以 `normalized.message.text[len(emitted_visible):]` 补发所有未发片段，包含先前保留的协议标记和 JSON。

这与纯文本降级“不创建 `ConclusionBlock`”一致，但会把内部协议显示到终端/Web 正文，并且会在长流结束时突然插入大段 JSON。合法块的测试已覆盖且不会泄漏；缺少截断、重复和非法 schema 的流式断言。应将一旦识别为受控块前缀的尾部视为内部通道：完整合法时转为 `ConclusionBlock`，非法时不转发该尾部并写入安全诊断，或在协议设计上明确并隔离一条可展示的错误提示。
