# 项目画像与完成审查闭环仍有三个可绕过或失效的边界

本轮实现已将 `src/tsm_agt/web/app.py` 纳入画像候选，并统一为纯内容 SHA-256；搜索的单文件采样和状态指纹熔断也通过了定向回归。P3 的 SDK、Web、CLI 都从 `get_project_profile_status()` 或同一任务事件投影获取展示数据，首次 refresh 的 `pending_refresh` 也已覆盖。仍有两条完成审查 fail-open：模型审查在画像缺失或未绑定时可接受否定结论，one-shot CLI 在没有审查器时可直接成功。真实 `web/app.py` 还因超过固定大小阈值失去 Web 结构标记，且不能被审查器读取补证。

Watch for: **confirmed** — 未绑定或缺失画像下的否定结论可被 `ModelCompletionAuditor` 判为 `PASS`；**confirmed** — one-shot CLI 在审查器未注册时跳过 Completion Audit 并转为 `SUCCEEDED`；**confirmed** — 156,129-byte 的真实 Web 入口被 128 KiB 截断规则排除在结构标记与 audit 读取之外。

**Verdict**: NEEDS_CHANGES

## High-level view

完成审查只有在画像候选存在时才对否定结论施加“必须读取所有候选”的约束。Task 尚未绑定 profile，或 profile 不可用时，输入没有 freshness/coverage 状态；模型返回 `PASS` 会直接穿过解析器。这把“画像缺失只能 NEEDS_EVIDENCE 或 UNDECIDABLE”的安全边界交给了模型。

CLI 的正常 production composition 会注册审查器，但 finalizer 将 `run_completion_audit()` 的 `None` 当作可成功结束的状态。任何缺少该可选适配器的 one-shot 运行都能绕过 P2 的独立审查，而 SDK 也保留了相同的 feature-disabled 成功分支。

画像的 source ref 与纯内容 hash 已正确生成，不过目标 Web 文件超过 128 KiB 后只保留路径候选；标记提取和 audit 补证都拒绝读取它。这会让最初事故涉及的内嵌 Web UI 失去结构化导航，也会把对该候选的否定结论固定导向人工复核而非自动证伪或返工。

1. **画像缺失时否定结论可被模型审查通过（高，confirmed）** — `run_completion_audit()` 对未绑定/缺失 profile 传入空 section，`ModelCompletionAuditor` 允许模型的 `PASS` 原样返回；应把 profile freshness/coverage 纳入输入，并在否定结论没有 FRESH、完整候选覆盖时 fail-closed 为 `NEEDS_EVIDENCE` 或 `UNDECIDABLE`。

## 画像缺失没有关闭否定结论的审查入口

**高严重度，confirmed。** `Kernel.run_completion_audit()` 只有 Task 已绑定 profile 且可加载对应 revision 时才提供 `profile_sections`。未绑定、画像缺失或不可读取时，它传入空元组，但 `CompletionAuditInput` 未携带 freshness 或覆盖状态。`ModelCompletionAuditor.audit()` 随后刻意跳过 profile conflict 的 preflight；`_parse_model_verdict()` 也只在空前提被打破、即存在 conflicting ref 时，才把负面 `PASS` 降级。

最小复现以空 `profile_sections` 创建“当前项目没有前端”的已通过确定性验收输入，再解析模型的 `PASS` JSON，结果为 `PASS` 且保留 `event:1`。这不是模型不确定性，而是解析器的确定性放行。它违反了 SPEC 对 profile `MISSING|STALE` 时只允许 `NEEDS_EVIDENCE` 或 `UNDECIDABLE` 的约束；应由 Runtime 在创建审查输入时标记 freshness，并由 `_preflight`/解析器无条件拒绝缺少完整画像覆盖的否定 `PASS`。

来源：`src/tsm_agt/core/kernel.py` 的 `run_completion_audit()`，`src/tsm_agt/adapters/completion_audit.py` 的 `_preflight()`、`_parse_model_verdict()`，`src/tsm_agt/core/completion_audit.py`。

## one-shot finalizer 将缺失审查器视为成功

**高严重度，confirmed。** `_finalize_standalone_agent_result()` 在确定性验收通过后调用 `run_completion_audit()`，但只有 audit 对象存在且其 verdict 不是带证据的 `PASS` 时才转入 `NEEDS_REVIEW`。审查端口未注册时返回 `None`，条件不成立，函数仍依次迁移 `FINALIZING` 和 `SUCCEEDED`。

这个分支已被现有 `StandaloneFinalizationTest.test_final_result_runs_verifier_and_ends_task` 覆盖：fixture application 没有传入 completion auditor，测试却断言任务成功。production composition 注册审查器不改变该函数对有效 application composition 的 fail-open 行为；CLI 本身不具备“无 audit 不得完成”的边界。应删除该成功回退或将端口改为 one-shot composition 的强制依赖。

来源：`src/tsm_agt/cli.py` 的 `_finalize_standalone_agent_result()`，`tests/test_cli_standalone_finalization.py`。

## 128 KiB 上限遮蔽目标 Web 入口的语义

**中严重度，confirmed。** `ProjectProfileBuilder._structural_markers()` 对超过 128,000 bytes 的文件直接返回空元组。当前 `src/tsm_agt/web/app.py` 实测为 156,129 bytes，因此项目画像有两个带纯内容 SHA-256 的 `ENTRYPOINT` source ref，却只有路径作为 summary/search text，缺少 `FastAPI`、`HTMLResponse`、`INDEX_HTML`、`<textarea` 或 `<button` 等任何 Web 标记。小型 synthetic fixture 因未越过阈值而无法覆盖真实工作区行为。

同一尺寸限制也位于 `collect_completion_audit_evidence()`；审查器对这个 profile candidate 不会产生 `AuditSourceEvidence`。安全上它会保持 `NEEDS_EVIDENCE` 而非错误 `PASS`，但对目标 Web UI 的负面结论无法自动补证、识别冲突或产生有依据的 rework。应在不把全文放入 profile/audit 输入的前提下，使用受限分块或入口级结构扫描，并记录可验证的覆盖范围。

来源：`src/tsm_agt/core/project_profile.py` 的 `_structural_markers()`，`src/tsm_agt/core/kernel.py` 的 `collect_completion_audit_evidence()`，`src/tsm_agt/web/app.py`。
