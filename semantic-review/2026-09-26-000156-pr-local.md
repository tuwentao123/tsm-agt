# V3 结论协议的可达性与输出隔离

本轮未提交改动把最终 Agent 回答改为 Task 与 Session 的联合提交，移除了旧唯一约束错误时的拆分写入回退；SQLite v1→v2 迁移也在同一事务中完成。`AGENT_DECIDES` 与 `OBSERVE_ONLY` 不再把 readiness/recovery/budget 生成的 Runtime 指令送入模型，Projector 只读取持久化事件，Session 读取仍按 subject 校验。Watch for: **confirmed**，OpenAI-compatible Provider 的受控结论通道在正常 Kernel 请求中不可达，且所谓 native 通道没有向 Provider 请求可验证的 schema；**confirmed**，非流式响应仍会把非法 `<tsm-conclusion-v1>` 原样放进用户可见正文。

**Verdict**: NEEDS_CHANGES

## High-level view

最终回答经由 `Kernel._commit_final_agent_result()` 和 `RuntimeStorePort.commit_session_and_task()` 联合写入；v2 迁移也已解除旧的 `(session_id, task_id)` 约束。非 legacy mode 会记录诊断但在请求前清空 recovery、预算和 readiness 的业务指令。

流式路径会扣留非法受控尾部，但结论协议尚未形成可达、可协商的端到端通道：Kernel 不会为 `native_structured_conclusion=False` 的 Provider 请求受控协议，默认 native 分支也只注入提示词而未协商结构化响应格式。

## 受控协议仅在测试中被手动请求

`Kernel._continue_agent_turn()` 与 `Kernel.run_text_turn()` 依据 `model.capabilities.structured_conclusion` 决定是否把 `ConclusionProtocolMode.REQUIRE_STRUCTURED` 交给模型。`OpenAICompatibleModelProvider` 又把这个能力直接等同于 `native_structured_conclusion`。因此配置 `native_structured_conclusion=False` 后，正式 Runtime 调用会传入 `OBSERVE`；`_conclusion_protocol_instruction()` 在该模式返回 `None`，受控块的 system instruction 根本不会进入请求。`tests/test_openai_compatible_model.py::test_require_structured_uses_controlled_protocol_when_native_field_is_unavailable` 直接构造 `REQUIRE_STRUCTURED` 请求，覆盖的是适配器局部行为，不能覆盖 Kernel→Provider 的实际协商链路。

默认路径同样不能证明 native 结论会由 Provider 返回。`_build_payload()` 仅在 `messages` 顶部插入一条要求 Provider 在 assistant envelope 新增 `conclusion` 字段的 system message，没有发送 JSON schema、`response_format` 或等价的受控 tool 定义。适配器虽然会被动读取 `message.conclusion`/`delta.conclusion`，但请求没有建立这个响应字段的外部协议。结果是实际 Provider 可合法返回普通 content，系统仅记录 `plain_text_fallback`；结论协议不具备所声明的协商保证。

## 非流式降级把内部块重新变成正文

流式实现的 `_suppress_streamed_conclusion_tail()` 已在 `_stream_complete_once()` 中处理非法尾部，新增的流式测试覆盖截断、重复、非法 JSON/schema 和尾随文本。然而 `complete()` 走 `_normalize_response()`，而 `_extract_conclusion()` 对同一组非法输入统一返回 `(text, None)`。`_normalize_response()` 随即追加 `TextBlock(text)`，把 `<tsm-conclusion-v1>` 和其中 JSON 原样作为用户正文返回；禁用 streaming 时 `stream_complete()` 又直接委托这个分支。

这使“非法受控块不泄漏”仅适用于 SSE。应将“已发现 opening marker”的状态传到共用规范化逻辑，成功时剥离并生成 `ConclusionBlock`，失败时删除整个协议尾部或失败本次响应；并补充 non-streaming 与 `streaming=False` 的同组断言。
