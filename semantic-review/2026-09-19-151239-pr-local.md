# 会话语义分流与无 Task 问答

本次改动将会话输入拆成模型提议的 `SessionRouteDisposition` 与 Kernel 的目录、置信度和状态校验，并为运行中的 Task 增加事件型输入通道。普通文本在审批和澄清等待状态会被 Runtime 门禁拒绝，运行中则可由分类器提出 `STATUS_QUERY`、`STEER` 或 `REPLACE`，再由 Kernel 记录和应用。纯问答确实不会创建 Task 或调用 `plan_task_spec`，但路由模型同时被赋予了直接生成并提交最终回答的职责，超出了“模型只提出路由”的边界。SessionContext 的新限界策略也没有同步更新既有测试，当前目标套件存在两项确定性失败。Watch for: **confirmed** 路由模型可绕过 Harness 直接向用户输出内容；**confirmed** SessionContext 回归测试失败，CI 无法通过。
**Verdict**: NEEDS_CHANGES

## High-level view

会话路由本身已把 Task 选择约束在持久化目录和 resume 候选内，且审批、澄清回复通过独立的结构化事件处理；普通文本不能被解释为授权或澄清答案。运行中输入的模型分类也被限制为有限 intent，并在等待审批或澄清时先被状态门禁截断。

`ANSWER` 却把路由和回答生成合并在同一次模型调用：模型不仅选择无 Task 路径，还提供会被 CLI 原样持久化和展示的 `answer_text`。这使 Harness 无法验证问答内容是否仍满足“纯问答”边界，也无法让专用问答执行路径承担内容生成责任。

SessionContext 已故意收缩详细 handoff 和历史资源上限，但对应测试仍要求旧的全量投影。这不是行为不确定性，而是当前实现与回归契约未同步，必须在合入前决定并固化新的有界合同。

## `ANSWER` 将路由模型变成最终回答模型

`ModelSessionInputResolver` 的 schema 将 `answer_text` 作为必填字段，并在 system prompt 中要求 `ANSWER` “include the complete user-visible answer”。Kernel 对该字段只校验非空、自包含和高置信度；它不将内容交给其他受控执行路径。CLI 收到 `SessionRouteDisposition.ANSWER` 后调用 `record_session_answer()`，随后原样输出 `agent> {answer_text}`，没有创建 Task，因而也不会进入 `plan_task_spec`。

这满足“不创建 Task/不跑 plan_task_spec”，却违反“模型只提出路由，Harness 校验”：路由模型现在拥有了直接向用户输出内容的能力。它可以在同一响应中把不属于纯问答的工作伪装为文本，Harness 无从审计该答案是否应转为 Task、是否需要工具或是否引用了受限上下文。应将 `answer_text` 从路由 schema、提示词和 `SessionInputDecision` 中移除；仅允许模型提议 `ANSWER`。Harness 接受该 disposition 后，调用与 routing 隔离的问答生成通道，或采用明确的确定性响应策略。**confirmed**：`src/tsm_agt/adapters/model_session_input/resolver.py:25-52,94-101`、`src/tsm_agt/core/kernel.py:1602-1612,2060-2099`、`src/tsm_agt/cli.py:1247-1273`。

## 有界 SessionContext 的测试合同已断裂

`SessionContextProjector` 新增 `detailed_task_summary_limit=4`、`historical_resource_limit=24` 和 `historical_question_limit=12`，并据此裁剪 `recent_task_summaries` 和 `historical_investigation`。但 `tests.test_session_context` 仍要求六个详细 Task 摘要，以及 40 个资源和 20 个问题。

使用 `PYTHONPATH=src python3 -m unittest tests.test_session_input_resolution tests.test_runtime_input_router tests.test_session_context tests.test_cli_chat tests.test_cli_sigint` 执行时，`test_all_task_summaries_enter_projection_before_token_budgeting` 和 `test_reference_catalogs_are_bounded_and_same_question_ids_do_not_collide` 因这些数值差异失败。前者实际得到 `task-4` 至 `task-7` 四项而非 `task-2` 至 `task-7` 六项，后者实际得到 24 个资源而非 40 个。新的限界可能是正确设计，但未更新的断言使回归套件失败，也没有证明纯问答积累后仍能保留所需的历史 Task handoff。应明确预算合同、更新断言，并补充“多轮无 Task 问答后引用历史 Task 产物”的端到端覆盖。**confirmed**：`src/tsm_agt/core/session_context.py:352-369,513-535,639-706`、`tests/test_session_context.py:145,460`。

SIGINT 集成未能在本机验证：CLI 测试环境缺少 `prompt_toolkit`，子进程无法启动；不把该环境依赖缺失归为本次改动缺陷。
