## “未实现 Web 前端”不触发否定结论的 fail-closed 分支

**高严重度，confirmed。** `src/tsm_agt/adapters/completion_audit.py` 的 `_has_negative_claim()` 仅匹配“没有 / 不存在 / 未找到 / not exist / does not exist / no ”；`src/tsm_agt/core/kernel.py` 在选择完整 profile sections 时又复制了同一判断。“当前项目未实现 Web 前端”未命中任一标记。于是 `_preflight()` 不校验 `profile_freshness`，`_parse_model_verdict()` 不计算未读的冲突 source ref，也不会要求 source coverage。

最小复现提供 `profile_freshness="FRESH"` 和一个指向 `src/tsm_agt/web/app.py`、未读取的 `ENTRYPOINT` section；Worker answer 为“当前项目未实现 Web 前端”，审查模型返回含 `event:1` 的 PASS。实际结果为 `{'verdict': 'PASS', 'requested': 0, 'model_calls': 1}`。同一工作区的 profile 构建实测 `app.py` 156,129 bytes，两个 source-linked section 的 marker 包含 `FastAPI HTMLResponse INDEX_HTML <html <textarea <button`，不是画像缺失造成的降级。

`src/tsm_agt/sdk/runtime.py` 和 `src/tsm_agt/cli.py` 都将“PASS 且存在 evidence_refs”迁移为 `FINALIZING` 后的 `SUCCEEDED`；不会重新解释 Worker 文本。因此该 phrase-classification 缺口可将“没有 Web UI/前端”的同义错误结论作为成功任务交付。应将 absence claim 从自由文本提取为受校验的结构字段；在完成该改造前，至少以保守的多语言模式覆盖“未实现”“无”“缺失”“未提供”“not found”“absent”等否定表述，并让无法分类的结束结论在 profile 已有候选时转为 `NEEDS_REVIEW`。
