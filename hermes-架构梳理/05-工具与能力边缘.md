# 05 · Hermes 工具与"能力在边缘"

> 来源 `/tmp/hermes-src`。每条带 `file:line`。
> 对应第二不变量（`AGENTS.md:10-30`）：**core 是窄腰，能力住在边缘**。

---

## 1. 工具不是注册表清单，而是"自注册模块的自动发现"

`tools/registry.py` 模块首行 docstring（`:1`）：

> *"Central registry for all hermes-agent tools: **each tool file calls ``registry.register()``** …"*

`tools/` 下 **267 个 `.py`**。**没有**中心 `TOOLS = [...]` 清单，也**没有**按名字分发的 `if/elif` 阶梯。

### 发现机制：AST 扫描 + 按 mtime 缓存

| 函数 | 行 | 作用 |
|---|---|---|
| `_is_registry_register_call(node)` | :59 | 认 `registry.register(...)` 调用表达式 |
| `_module_registers_tools(module_path)` | :69 | **只看模块体语句**（或模块级 `for` 的 body）是否调用 `register`；*"helpers registering inside a function are skipped"*；*"Table-driven modules register several tools from one loop, still at import time"* |
| `_tool_module_candidates(tools_path)` | :87 | 候选模块（README 说明用 AST 过滤，避免 import 所有文件） |
| `discover_builtin_tools(tools_dir)` | :96 | import 自注册模块并返回模块名 |
| `_discovery_cache_path/_load_discovery_cache/_save_discovery_cache` | :144,:154,:167 | 发现结果落盘缓存 |

缓存键是 `abs_path -> [mtime, size, registers]`（`:127`）。注释（`:112`）：*"…register from a checkout and vanish from an installed wheel."*

**⇒ 加一个工具 = 加一个文件；零处中心修改。**

## 2. `ToolEntry` —— 一个工具的全部元数据（`:182-198`）

```python
class ToolEntry:
    """Metadata for one registered tool (identity semantics: restore/CAS paths compare ``is``)."""
    name: str
    toolset: str
    schema: dict
    handler: Callable
    check_fn: Optional[Callable]          # 运行时可用性探测
    requires_env: list
    is_async: bool
    description: str
    emoji: str
    max_result_size_chars: int | float | None = None
    dynamic_schema_overrides: Optional[Callable] = None   # 每次 get_definitions() 浅合并的零参回调
```

* `check_fn` + `_CHECK_FN_TTL_SECONDS = 30.0`、`_CHECK_FN_FAILURE_GRACE_SECONDS = 60.0`、`_CHECK_FN_CACHE_MAX = 512`（`:223-227`）⇒ **可用性探测有 TTL 缓存**。
* `dynamic_schema_overrides` 注释（`:195-196`）：*"for fields tracking runtime config (delegate_task's description reflects limits)"*。
* `toolset` + `register_toolset_alias(alias, toolset)`（`:526`）⇒ 工具按 toolset 分组，别名可注册（碰撞只 warning 不抛）。

## 3. `register(...)` —— 导入时调用（`:666-671`）

```python
def register(self, name, toolset, schema, handler,
             check_fn=None, requires_env=None, is_async=False,
             description="", emoji="", max_result_size_chars=None,
             dynamic_schema_overrides=None, override=False, scope=None)
```

docstring：*"…``override=True`` is an explicit opt-in for plugins replacing a built-in implementation (e.g. a headed-Chrome browser backend); **without it, cross-toolset shadowing is rejected**."*

**注册时即校验**（`:675-685`）：

> *"Reject malformed schemas at registration, not at request time: a non-dict ``parameters`` (e.g. a list) serializes into every provider request and 400s the whole turn far from the offending plugin. Failing here names the culprit instead."*
> → `schema` 非 dict 或 `schema["parameters"]` 非 dict ⇒ 直接 `ValueError`。

**插件越权**：`_PluginOverridePolicy`（`:200`）、`_OVERRIDE_DENIED_MSG`（`:209`）、`register_plugin_override_policy`（`:547`）、`snapshot/restore_plugin_override_policy`（`:559,:567`）。注释（`:550-551`）：*"The identity-bearing result lets unload/reload revoke a stale authorization without losing attribution."* ⇒ 覆写授权是**按 scope 的可撤销对象**，不是布尔开关。

## 4. 定义 → 请求：`get_definitions(tool_names, quiet=False)`（`:843`）

docstring：*"OpenAI-format schemas for the requested tools whose ``check_fn`` passes (or is absent). Probes use the ~30 s TTL cache so ``hermes tools enable`` lands quickly."*

* 输入是 **`Set[str]`**（这轮要哪些），不是"全部工具"；
* `check_fn` 不过 ⇒ 静默跳过（quiet 控制是否 debug 日志）；
* `{**entry.schema, "name": entry.name}`；`dynamic_schema_overrides()` 结果浅合并（异常只 warning，`:860-865`）。

⇒ **每轮请求的工具集是"名字集合"驱动的子集**，与 `session_tools`/pinned tools 相关（`conversation_loop._restore_pinned_tools:700`、`_refresh_bot_chat_tools:722`）。

## 5. 分发：`dispatch(name, args, *, scope=None, **kwargs)`（`:893-921`）

docstring：*"Execute a tool handler by name: async handlers bridged via ``_run_async()``, results normalized, **every exception returned as ``{"error": ...}``**."*

* 未知工具 ⇒ `tool_error(f"Unknown tool: {name}")`（**不抛**）；
* **插件契约**（`:900-903`）：*"optional context kwargs (task_id, session_id, user_task, parent_agent, ...) are **signature-inspected** like hook payloads, so a narrow ``handle(args)`` plugin handler is not broken by every field the dispatcher injects (#68318)."* → `_kwargs_accepted_by(entry.handler, kwargs)`；
* `is_async` ⇒ `model_tools._run_async(...)` 桥接；
* 异常 ⇒ 记日志（`_bound_error_text`）+ `model_tools._sanitize_tool_error(raw)`（*"so framing tokens/CDATA/fences in exception text aren't structural noise"*）⇒ 返回 `{"error": …}`；sanitizer 自身失败也不阻断传播。

**错误文本有界**：`_MAX_TOOL_ERROR_CHARS = 2048`（`:26`）、`_TOOL_ERROR_TRUNCATION_MARKER = "… [truncated]"`（`:27`）、`_MAX_LOGGED_ERROR_CHARS = 8192`（`:29`）、`_bound_error_text`（`:32`）、`_bound_json_error_result`（`:42`）。

## 6. 工具调用校验：`agent/turn_tool_validation.py`

模块 docstring（`:1-8`）原文，这里就是"工具错误如何回到模型"的全部策略：

> *"Tool-call validation for the conversation turn loop: **unknown tool names** (with auto-repair and the **3-strike partial exit**) and **malformed JSON arguments** (retry, then recovery tool results).
> **Role alternation is preserved on every path**: an invalid batch is answered with **tool-role error results (never a user message)**, and the exits **close any open tool-result tail (#48879)**."*

产物（`:26-37`）：

```python
@dataclass
class ToolValidationVerdict:
    """``action``: ``"ok"`` (dispatch the calls), ``"continue"`` (re-issue the API call —
    error results / retry state were recorded) or ``"return"`` (terminal partial result in
    ``result``). ``mixed_invalid_batch`` is True when the batch contains BOTH valid and
    unknown tool names: only the invalid calls get error results, the valid ones run."""
```

* `_append_tool_error_results(messages, tool_calls, content_for)`（`:39`）：*"One tool-role result per call so **every tool_call keeps a matching result**."*
* `_partial_exit(agent, messages, conversation_history, api_call_count, final_response)`（`:55-70`）：*"Terminal partial result. Prior retries or an earlier tool batch leave a tool-result tail; **close it as interrupt aborts do so the next turn is not tool→user (#48879)**. **This path never reaches finalize_turn, so persist here.**"* → `close_interrupted_tool_sequence(...)` + `agent._persist_session(...)` + `stamp_failure({... "completed": False, "partial": True ...}, "truncated", True)`。
* `_preview_name(name)`（`:37`）：名字截断 80 字符。

**⇒ 三条硬约束**：(a) 每个 `tool_call` 必须有配对 result；(b) 错误也必须是 tool-role；(c) 终端出口必须**关闭悬空的 tool-result 尾**，否则下一轮角色交替坏掉。
