# 06 · 端到端执行流程：从用户输入到会话任务完成

> 来源 `/tmp/hermes-src`。**每条带 `file:line`。**
> 这一册把所有分册串成一条链路，回答："一条用户输入，怎么走到任务完成？"

---

## 0. 一句话结论

**Hermes 的多轮没有"多轮控制器"。** 全局只有一个**输入队列**；每轮结束后，goal 判定若说"继续"，就把一条**续跑提示塞回同一个队列**。多轮 = 队列里还有东西。

---

## 2. 阶段逐段核实

### 阶段 1 · 输入队列是唯一的驱动源

`_pending_input = queue.Queue()`（`hermes_cli/cli_init_mixin.py:362`）。消费者是 REPL worker 线程：

```python
def _tui_process_loop(self):
    """REPL worker thread: drain ``_pending_input``, run idle housekeeping, dispatch each input."""
    while not self._should_exit:
        try:
            user_input = self._pending_input.get(timeout=0.1)
        except queue.Empty:
            if not self._agent_running:
                self._tui_idle_tick()
            continue
        self._tui_process_one_input(user_input)
```
`hermes_cli/cli_tui_runtime_mixin.py:31-47`

**谁往队列里放东西**（这就是全部触发源）：

| 来源 | 位置 |
|---|---|
| 真实用户输入 | `cli_chat_turn_mixin.py:520,600` |
| **goal 续跑提示** | `cli_loops_mixin.py:726`（判定 continue 后） |
| interrupt 消息 | `cli_chat_turn_mixin.py:429` |
| retry 消息 | `cli_loops_mixin.py:201`（*"process_loop sends it to the agent"*） |
| steering 残留 | `cli_chat_turn_mixin.py:607` |

**空转时的空闲钩子**（`_tui_idle_tick`，`:49-60`）：配置/MCP 变更检查、termios 漂移自愈、进程通知排空、`_maybe_fire_loop_tick`、**`_maybe_resume_parked_goal`**。

### 阶段 2 · 路由

`_tui_process_one_input`（`:62`）按顺序判定：文件拖入 → `/resume` 数字选择 → `!` shell → slash 命令 → **否则是聊天轮**。注意 `_tui_idle_tick` 只在 agent 没在跑时才做空闲维护（`:38`）。

### 阶段 3 · 一轮

`AIAgent.chat(message)` = `run_conversation(message, …)["final_response"]`（`agent/turn_facade.py:220`）；`run_conversation` 转发前先取 **session turn lease**（`turn_facade_lease.py`，见 00 册 §4）。
一轮内部结构 = 02 册（`_LoopState` + `_run_phase` + 主 while 相位序 + `finalize_turn`）。
出口解释 = 03 册（前缀表 + `completed` 表达式）。

### 阶段 4 · 轮后钩子

```python
hooks = [("loop completion", self._post_turn_loop_completion)]
if final_text.strip():
    hooks.insert(0, ("goal continuation", self._post_turn_goal_continuation))
```
`gateway/run_goals.py:332-334`

三条硬约束：
1. **空响应不判**：`gateway/run_goals.py:330-331` 注释 *"Empty interrupted/errored responses must not drive /goal"*；CLI 侧同义（`cli_loops_mixin.py:706-710`：*"Empty/whitespace responses are almost always transient failures (API error, empty stream): judging would say 'continue' and trip the parse-failure backstop."*）
2. **通知延后到投递之后**：`:303-305` *"Deferred until the visible final response is delivered, else '✓ Goal achieved' precedes it."*
3. **judge 是同步 aux-LLM 调用（10–40 s）**，必须丢线程池：`:293-296` *"would block Discord heartbeats"*，且要用 `_run_in_executor_with_context` 携带 profile secret scope。

### 阶段 5 · goal 判定

`GoalManager.evaluate_after_turn(final_response, user_initiated=True, background_processes=…, active_delegations=…)` → `{"status", "should_continue", "continuation_prompt", "message", …}`（`hermes_cli/goals.py:1479,1077`）。
内部顺序：**gate → judge → decision**；`waiting_*` 屏障期间直接 `should_continue=False` 且不消耗 turn（04 册 §4）。
进程/委派会把 goal **停泊（park）**而不是空转：`:285-291` 只统计**本会话**的进程（*"subagents' pollers must not park the parent's goal"*）。

### 阶段 6 · 续跑注入 —— 闭环点

| 表面 | 入队方式 | 位置 |
|---|---|---|
| CLI | `self._pending_input.put(prompt)` | `cli_loops_mixin.py:722-728` |
| Gateway | `adapter FIFO enqueue` | `gateway/run_goals.py:306-316` |

Gateway 的注释（`:309`）：*"Enqueue via the adapter's FIFO **so a user message already in flight preempts naturally**."*
CLI 的对应保护：`:724` 只在 `prompt` 非空时入队。

**⇒ 续跑消息与真实用户消息走同一条通路（同一队列、同一路由、同一个 `run_conversation`）。区别仅是 synthetic 标记。这是"多轮"的全部机制。**

## 3. 终止条件（什么时候真的完成）

| 条件 | 出处 |
|---|---|
| goal 判定 `should_continue` 为假 | `goals.py:1077`（`_decision`） |
| `turns_used >= max_turns`（默认 **20**） | `goals.py:32,1502` |
| judge 连续解析失败 → 自动暂停 | `GoalState.consecutive_parse_failures`（04 册 §4） |
| judge 连续传输失败 → 自动暂停 | `consecutive_transport_failures`，注释：*"a broken API key returns 401 every call and must auto-pause instead of burning the budget on an unreachable judge"* |
| 不可由 agent 修复的条件 → **暂停不重试** | `goals.py:374-394`：*"**no agent turn can fix it**, so the caller pauses instead of retrying"* |
| 用户 Ctrl+C → pause | `cli_loops_mixin.py:700`（`mgr.pause(reason="user-interrupted (Ctrl+C)")`） |
| 没有 goal 在跑 | `gateway/run_goals.py:282`（`not mgr.is_active()` 直接返回） |

**注意区分两个预算**（这是最容易混的）：
* `agent.max_iterations` 默认 **500** —— 一轮内的 **API 调用**预算（`agent/AGENTS.md:15`）
* `GoalState.max_turns` 默认 **20** —— 会话级 **轮次**预算（`goals.py:32`）

## 4. 与 tsm-agt 的结构对照（这是重构的靶子）

| 环节 | Hermes | tsm-agt 现状 | 差距性质 |
|---|---|---|---|
| **驱动源** | 一个输入队列；续跑提示与真实输入**同路** | `SessionTextInput` → `dispatch_input_event` → `SessionInputDecision`（ANSWER / CREATE_TASK / STEER / REPLACE / INTERRUPT），`sdk/runtime.py:386-424,853-893` | **语义路由 vs 队列**：tsm-agt 每条输入都要先被**判定成什么**，Hermes 不判 |
| **会话记录** | `messages` 表，逐轮追加、逐轮重放（含 tool 角色与 `api_content`） | Session 只有 `task_ids`/`active_task_id`/两个计数器（`core/session.py:81-95`）；内容靠 `SessionContextProjector.project()` **每轮重投影**（`core/session_context.py:582`） | **持久 vs 投影**：投影有损 ⇒ 多轮接不上 |
| **历史选择** | 按时间全量重放，逐字节稳定 | 按 **Task 血缘**成员资格，且声明 *"Recency is never an eligibility criterion"*（`core/session_context.py:212-227`） | **追加 vs 过滤** |
| **一轮** | `_LoopState` + `_run_phase` + 唯一 `action` 枚举（`conversation_loop.py:1385-1498`） | `kernel.py::run_agent_turn`（`:10762`，18,079 行 god file，循环 `:12091`） | **相位化 vs 交织** |
| **轮后判定** | `evaluate_after_turn` = gate → judge → decision，**在轮外**（`gateway/run_goals.py:296`） | 完成判定与终端状态散在 56 个站点（TerminalStateConvergenceTest 棘轮） | **轮外单点 vs 轮内多点** |
| **续跑** | 判定产出一条 prompt，**塞回队列** | RESUME 被规范化为**全新 FOLLOW_UP Task** + "bounded authority-free handoff"（`sdk/runtime.py:371-375`） | **续跑 vs 换 Task**：换 Task 就得丢历史 |
| **权威** | 无 Task 级权威；审批在工具层（`tools/approval.py`） | Task 级 authority，`ContextScope` 按血缘过滤（`core/session_context.py:173-220`） | **本项目独有**，见重构方案 M3 |

**最重要的三条对照**：

1. **Hermes 不判定输入是什么，tsm-agt 判定。** Hermes 的输入只有"一条消息"；tsm-agt 每条消息都要过路由器决定 ANSWER/CREATE_TASK/STEER/REPLACE。路由器一多，路径就多，失败面就大。
2. **Hermes 的历史是追加的，tsm-agt 的是投影的。** 这就是"多轮跑不通"的机械原因。
3. **Hermes 的完成判定在轮外单点，tsm-agt 的在轮内 56 处。** 这就是"不知道如何完成闭环"的机械原因。

## 5. 这套流程里可直接借用的四个性质

1. **单一驱动源**：所有输入（真实 + 续跑 + 中断 + 重试）走同一个队列、同一个路由、同一个轮函数。多轮不需要额外控制器。
2. **续跑与真实输入同权，但真实输入优先**（`run_goals.py:309` 的 FIFO 语义）。
3. **判定在轮外**：轮只负责"跑完并解释出口"，"是否继续"是轮之后的一次判定（`evaluate_after_turn`）。
4. **暂停而非空转**：等进程/委派/人时用 `waiting_*` 屏障（不消耗 turn），修不了的条件直接 pause。
