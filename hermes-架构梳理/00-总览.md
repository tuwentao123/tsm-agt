## 1. 定位（`AGENTS.md:10-19` 原文）

> *"Hermes is a personal AI agent that runs **the same agent core across a CLI, a messaging gateway (Telegram, Discord, Slack, ~20 platforms), a TUI, and an Electron desktop app**. It **learns across sessions** (memory + skills), **delegates to subagents**, **runs scheduled jobs**, and **drives a real terminal and browser**. It is **extended primarily through plugins and skills, not by growing the core**."*
>
> *"**The self-improving AI agent** — creates skills from experience, improves them during use, and runs anywhere"*（`pyproject.toml:4`）

**⇒ 这不是"一个 agent 库"，是"一个 core + 一整套 surface + 一套扩展系统"的平台。**

## 2. 两条不变量 —— 所有设计决策的透镜（`AGENTS.md:21-30`）

| # | 不变量 | 原文要点 | 落点 |
|---|---|---|---|
| 1 | **Per-conversation prompt caching is sacred** | 长会话逐轮复用缓存前缀；任何**改动历史上下文 / 换 toolset / 重载 memory / 重建 system prompt** 都会击穿缓存、成倍放大用户成本。**唯一例外是上下文压缩。** 改 system-prompt 状态的 slash 命令必须**cache-aware**：默认延迟失效（下个会话生效）+ 显式 `--now`（范例 `/skills install --now`） | `agent/AGENTS.md:56-62`、`turn_request_assembly.py:111-113,193-221`、`turn_context.py:1197-1206` |
| 2 | **The core is a narrow waist; capability lives at the edges** | **每个模型工具在每次 API 调用都被发送**，所以新增 *core* 工具的门槛极高。新能力应以 CLI 命令 + skill、service-gated tool、或 plugin 到达 | `tools/registry.py`、Footprint Ladder（`AGENTS.md:133-152`） |

推论（`AGENTS.md:154-175`）：**Surface capability is a property of the SESSION, never of the process env.** 客户端与后端是两台机器；`HERMES_DESKTOP=1` 只表示"这个后端是 app 启的"，**不表示"有 GUI 在看"**。所以 `check_fn` 只回答可达性/opt-in，**不回答 surface**；surface 由**命名 toolset** 决定，由 `_load_enabled_toolsets(platform)` 折叠进来。检验法：*"if the capability still makes sense with the client on another machine, it is session-scoped."*

## 4. 装配与依赖链（权威声明）

**依赖链**（`AGENTS.md:229-230` 原文）：
> `tools/registry.py`（无依赖）← `tools/*.py`（导入时 register）← `model_tools.py`（发现）← `run_agent.py`, `cli.py`, `batch_runner.py`, `environments/`

**构造**（`agent/AGENTS.md:7-19`）：
* `run_agent.py` 是公共 facade；`AIAgent` 由 mixin 拼装（`turn_facade.py`、`client_lifecycle.py`、`stream_delivery.py`、`session_persistence.py`、`compression_facade.py` …）；
* 构造走 `agent/agent_init.py::init_agent`；`AIAgent.__init__` 收 **~60 个参数**；
* 一轮 = `agent/conversation_loop.py::run_conversation`，由 `AIAgent.run_conversation` 转发，**转发前先取 session turn lease**（`turn_facade_lease.py`）；
* 对外的简单接口是 `chat(message) -> str`；正式接口 `run_conversation(user_message, system_message=None, conversation_history=None, task_id=None) -> dict`（返回 `final_response` + `messages`）；
* `max_iterations` 默认 **500**，与 subagent 共享（注意与 `goals.py` 的 `DEFAULT_MAX_TURNS=20` 是两回事：前者是 API 调用预算，后者是 goal 轮次预算）。

**入口**（`pyproject.toml:569-572`）：`hermes` → `hermes_cli.main:main`；`hermes-agent` → `agent.legacy_cli:main`；`hermes-acp` → `acp_adapter.entry:main`。

## 5. 轮循环的形状（`agent/AGENTS.md:23-45`）

**全同步**，带中断检查、预算跟踪、一次"宽限调用"。文档给的心智模型（原文）：

```python
while (api_call_count < self.max_iterations and self.iteration_budget.remaining > 0) \
        or self._budget_grace_call:
    if self._interrupt_requested: break
    response = client.chat.completions.create(model=model, messages=messages, tools=tool_schemas)
    if response.tool_calls:
        for tc in response.tool_calls:
            messages.append(tool_result_message(handle_function_call(tc.name, tc.args, task_id)))
        api_call_count += 1
    else:
        return response.content
```

**真实实现已在 `02-轮循环与相位协议.md` 核实**（这一段只是文档的心智模型）：
`run_conversation:1695` → `_run_conversation_turn:1533`（`_LoopState` + 主 `while` @`:1636`）→ `finalize_turn:1684`。
每个相位由 `_run_phase:1480` 调用：**按参数名从 `_LoopState` 取输入**，**按字段名把 verdict 写回 `_LoopState`**；控制流只有一个 `action` ∈ {ok, continue, break, return}。中断检查在 `begin_iteration` 相位里，不在 `while` 头。

**每次迭代的每个相位都是独立兄弟文件**（这是"改一处只动一个 ~600 行文件"的关键）：
`turn_preflight*`、`turn_iteration_prep`、`turn_request_assembly`/`turn_api_request`、`turn_api_call`、`turn_api_error`、`turn_response_intake`/`turn_response_check`、`turn_empty_response`、`turn_tool_round`/`turn_tool_validation`、`turn_overflow`、`turn_truncation`、`turn_context_compaction`、`turn_recovery`、`turn_recovery_autorecover`（耗尽后的 wait-and-retry 阶梯）、`turn_retry_state`、`turn_stop_gates`、`turn_liveness`、`turn_usage`、`turn_final_response`、`turn_finalizer`、`turn_summary`。
定位方式（原文）：*"Find the phase with `grep -rn "def X" agent/turn_*.py`."*

消息格式：OpenAI 的 `{"role": "system|user|assistant|tool", ...}`；reasoning 存 `assistant_msg["reasoning"]`（`:47-48`）。
**Agent 级工具**（`todo`、`memory` …）由 `agent/tool_executor.py` 经 `agent/inline_tool_executors.py` 的 `INLINE_TOOL_EXECUTORS` **表**在 `handle_function_call()` 之前拦截；新增方式（原文）：*"register in that table (**no `if name == ...` chain**)"*，范例 `tools/todo_tool.py`（`:50-52`）。

## 6. 消息流不变量（`agent/AGENTS.md:54-74`，每次改动都要对照）

1. **Prompt caching 不得被破坏**：system prompt 在会话生命期内**逐字节稳定**；**唯一的上下文变更就是压缩**。任何中途必须注入的内容**骑 user message 或 tool result，绝不骑 system prompt**（skill slash 命令经 `agent/skill_commands.py` 以 user message 注入；子目录 `AGENTS.md` 提示 `agent/subdirectory_hints.py` 追加到 **tool result**，超过 `_MAX_HINT_CHARS=32_000` 头尾截断，截断只记日志、"never queued as a chat status warning"）。
2. **严格角色交替**：绝不出现两条同角色相邻；**绝不中途注入合成 user message**。唯一例外 `/steer`——作为**独立 user 行**放在 tool result 之后（`assistant(tool_calls) → tool → user` 在所有 provider 路径都合法），**绝不涂抹到已持久化的 tool 行**（append-only 持久化会与活跃请求分叉）。**cron 投递因此放在自己的会话里。**
3. **Context files**（`agent/prompt_builder.py`）只在**启动时从 CWD** 加载且有上限（`CONTEXT_FILE_MAX_CHARS` / 由上下文窗口推出的动态上限 / `context_file_max_chars`）；**绝不把安装树里的 `AGENTS.md` 当项目上下文**（PR #64611）；子目录提示拒绝工作目录之外的路径，以免 `~/.codex/AGENTS.md` / `~/.claude/CLAUDE.md` 混入。
4. **`_last_resolved_tool_names` 是 `model_tools.py` 里的进程级全局**；`tools/delegate_tool.py::_run_single_child()` 在子 agent 执行前后保存/恢复它，读它的代码在子运行期间可能看到**暂时过期**的值。

## 7. 代码形状契约（`AGENTS.md:232-267`）—— 比"架构"更硬

### Facade + siblings（2026-09 分解）
每个前 god-file = **facade**（公共入口 + 别人 import 的名字）+ **同目录的 `<stem>_<topic>.py` 兄弟**，每个兄弟管一个主题。已声明最大族：`hermes_state.py`(21)、`gateway/run.py`(15)、`tools/mcp_tool.py`(15)、`hermes_cli/kanban.py`(14)、`hermes_cli/web_server.py`(13 + 24 routers)、`hermes_cli/auth.py`(12)、`tools/browser_tool.py`(11)、`cli.py`(12 个 `hermes_cli/cli_*_mixin.py`)、`run_agent.py`(`agent/turn_*.py` 等)。

规则：
* **按主题找代码，不按 facade**：`grep -rn "def name" <dir>/<stem>_*.py`。*"Reading the facade first is the expensive way"*（`evals/codebase_navigability/`）。
* 兄弟之间可互相 import，也可在**函数内** late-import facade；但 **facade 不在模块级 import 兄弟、同时又被该兄弟在模块级 import**。
* **Patch where production reads**：兄弟常在函数内 `from <facade> import name`，所以 `monkeypatch.setattr(facade, "name", ...)` 才是缝；打在定义模块上会**静默通过**（盲目重指向曾打破 130+ 测试）。
* **不要重建 god file**：**文件 ~2000 行**、**函数 ~300 行 / 圈复杂度 30** 就是"先按 `<stem>_<topic>` 拆、单独一个 commit"的信号；**新行为进新兄弟，绝不追加到 facade**。
* **禁止 keyed on name/kind 的 `if/elif` ≥ 4 分支**——用 dict/table → handler（范例 `cli.py` 的 `_SLASH_DISPATCH`、gateway 的 `_command_handler_table`）。
* **禁止 re-export shim**（"让旧名字还能 import"）。内部路径不是 API；一次性兼容层已移除、**永不重新引入**。
* **移动符号必须同一个 PR 修文档**：grep `website/docs`、`skills/`、每个 `AGENTS.md` 找旧 `path.py` + 符号（一次重构后有 23 个文档文件过期）。

### 通用形状
* 不要"纵深防御"包装、不要在不会失败的代码上 `try/except: pass`、不要没人设的 flag。
* docstring/注释**留 WHY，砍 WHAT**。
* **绝不用 argv 子串推断进程身份**（`"serve" in cmdline`）——这是约 10 个 fleet-update issue 的根因（#90778 等）。

## 8. 扩展模型

### 8.1 Footprint Ladder（`AGENTS.md:133-152`）—— 新能力选最高（足迹最小）的一档

| 档 | 形态 | 说明 |
|---|---|---|
| 1 | **扩展现有代码** | 已存在东西的变体。**零新表面。** |
| 2 | **CLI 命令 + skill** | 配置/状态/基础设施能表达成 shell 命令时；agent 依 skill 跑 `hermes <subcommand>`。**订阅、定时任务、服务设置的默认档**（`hermes webhook`、`hermes cron`、`hermes tools`） |
| 3 | **Service-gated tool（`check_fn`）** | 需要结构化参数/返回**且**只在某前提配好后才出现。注意：**变化于 SESSION 的能力**（谁在看）应由 toolset resolver 折叠的**命名 toolset** 提供，不是 `check_fn` |
| 4 | **Plugin** | 第三方/小众/用户特定；`~/.hermes/plugins/` 或 pip 包，运行时发现 |
| 5 | **MCP server（在 catalog 里）** | 确实是工具但不核心。**零永久 core-schema 足迹**，任何 MCP host 可复用，经内置 MCP 客户端到达 |
| 6 | **新 core tool** | 仅当**基础、几乎人人有用、且 terminal + file 或 MCP 都到不了**时（terminal、read_file、web_search、browser_navigate） |

### 8.2 插件五种发现系统（`plugins/AGENTS.md:53-61`）

| 类型 | 位置 | 发现 | 备注 |
|---|---|---|---|
| **General** | `plugins/<name>/`、`~/.hermes/plugins/`、`./.hermes/plugins/`、pip entry points | `PluginManager`（`hermes_cli/plugins.py`），**later-wins** | `register(ctx)` 注册 hooks（`pre/post_tool_call`、`pre/post_llm_call`、`on_session_start/end`）、工具（`ctx.register_tool`）、**CLI 子命令**（`ctx.register_cli_command`，argparse 树在启动时接入 `hermes`，**不用改 `main.py`**）、语言包 |
| **Memory provider** | `plugins/memory/<name>/` | bundled → `$HERMES_HOME/plugins/` → `./.hermes/plugins/`（需 opt-in `HERMES_ENABLE_PROJECT_PLUGINS`）→ entry points；**bundled-first** | 由 `memory.provider` 按名激活，所以放入的目录**不得遮蔽**已发布的（与 general 相反）。实现 `MemoryProvider` ABC（`agent/memory_provider.py`），由 `agent/memory_manager.py` 编排：`sync_turn`/`prefetch`/`shutdown`/可选 `post_setup` |
| **Model provider** | `plugins/model-providers/<name>/` | `providers/__init__.py._discover_providers()`，**lazy**，首次 `get_provider_profile()`/`list_providers()` 时；bundled → `$HERMES_HOME/plugins/model-providers/` → legacy `providers/<name>.py` | `__init__.py` 在 load 时 `providers.register_provider(ProviderProfile(...))`；**last-writer-wins**。`PluginManager` 只记录 manifest、**不 import**（会双实例化） |
| **Context engine / image-gen 等** | `plugins/context_engine/`、`plugins/image_gen/` … | ABC + orchestrator + 每插件一目录 | 插到 `agent/context_engine.py`、`agent/image_gen_provider.py` |
| **Platform adapter** | `plugins/platforms/<name>/adapter.py` | gateway | token-lock 与 scoped-secret 规则见 `gateway/AGENTS.md`（`irc`、`feishu` 是范例） |

**发现时机陷阱**（`plugins/AGENTS.md:63-73`）：`discover_plugins()` **只作为 import `model_tools.py` 的副作用**运行；不 import 就读插件状态的代码必须显式调用（幂等）。非 force 的 `discover_plugins()` 在 `_discovered` 上短路；**每个中途加载路径（任意表面的 install/enable/update、`reload-plugins`）都跑 `discover_plugins(force=True)`**。辅助 LLM 调用（起标题、压缩、MoA、vision）触发 `pre/post_auxiliary_call`，**绝不触发** turn 级的 `pre/post_api_request`（#79733）。

**多 profile**（`plugins/AGENTS.md:75-85`）：一个进程服务多个 profile，所以 provider **绝不**把 `initialize()` 拿到的 `hermes_home` 当"那个"home 缓存（用 `hermes_home_key()` 按每次调用传入的 home 索引）；**绝不为凭据读 `os.environ`**（用 `agent.secret_scope.get_secret`，`check_fn` 也是）；后台工作必须经 `agent.memory_provider.spawn_context_thread`，**不得裸 `threading.Thread`**（否则无 scope、失败关闭或写进启动 profile 的租户）。

**本地兼容契约**（`plugins/AGENTS.md:87-104`）：兼容性是**行为契约**，不是单体 `PLUGIN_API_VERSION`。hook payload 以**关键字字段**增加、回调做签名内省；**永不删除/改名 `PluginContext` 方法**；未知 manifest 字段忽略；新 provider 方法给默认实现；弃用要**每进程一次警告 + 文档替换/迁移说明 + ≥2 个后续 minor 版本**才移除。兼容测试**通过真实发现路径加载 frozen 插件并断言结果**。

**"插件绝不碰 core"**（`plugins/AGENTS.md:7`，Teknium 2026-05）：插件在"我们提供的 ABC/hook"内工作；若需更多，**放宽通用插件表面，绝不在 core 里特判它**。**第三方产品不进 core 树**（`plugins/AGENTS.md:17` 起）：可观测后端、厂商 SaaS 连接器等**不得落在 `plugins/` 下**——发**独立插件仓库**（`~/.hermes/plugins/` 或 pip entry point）。"这是耦合决策，不是质量门槛。"

## 12. 工程纪律（对移植同样重要）

* **修真 bug**：在当前 `main` 复现症状，**指到出问题的确切行**，并**修整个 bug 类**（含兄弟调用路径）。
* **先验证前提再断言**（`AGENTS.md:104-131`）：最常被关的 PR 原因是**前提错误**或**把有意设计当缺口**。*"如果指不出 bug 显形的确切行、也说不出修复改变了该行的行为，前提就是未验证的。"* 用 `git log -p -S "<symbol>"` 读原始意图。
* **行为契约而非快照**（`AGENTS.md:474-485`）：禁止 change-detector 测试（断言模型目录、`_config_version`、枚举数量、硬编码列表）。要断言**两块数据的关系**。
* **禁止在测试里读源码**（`AGENTS.md:487-502`）：读 `.py`/`.ts` 文件文本 = 测源码形状，**直接禁止**。应把逻辑抽成纯函数/可注入再调用。
* **E2E 校验而非绿的单测 mock**（`AGENTS.md:65`）：凡碰解析链、配置传播、安全边界、远程后端、文件/网络 I/O，必须对**临时 `HERMES_HOME`** 跑真实路径真实 import；碰 profile scope 时要跑两个（A→B→A）。
* **禁止投机基础设施**（`AGENTS.md:75-77`）：没有具体消费者的 hook/回调/扩展点不要加。*"Adding a hook is easy; removing one after plugins depend on it is hard."*
* **依赖精确钉版**（`pyproject.toml:20-40`）：每个直接依赖 `==X.Y.Z`，**不用范围**（2026-05-12 因 Mini Shai-Hulud 蠕虫击中 `mistralai` 而收紧）。改 pin 后跑 `hermes pm lock`。**`dependencies` 只放每次会话都用的包**，provider 专属的进 extra。

## 13. 对 tsm-agt 的宏观可迁移结论（每条都有 Hermes 出处）

> 以下是**从源码读出的对照事实**，不是实施方案。

1. **"一轮会话经常跑不通"的根因形态**：Hermes 把一轮拆成 **30+ 个相位兄弟**，每个有明确输入输出与不变量（`agent/AGENTS.md:38-45`）；tsm-agt 把一轮摊在一个大 runtime 里，于是每次修都要碰全局。
2. **"多轮会话运行不了"的根因形态**：Hermes 把**持久 transcript / wire 副本 / 当时真实字节**分成三份（01 册），并有一条**固定的组装顺序**（`turn_request_assembly.py:111-113`）；角色交替与 tool-result 配对是**逐个出口都要满足的硬约束**（`turn_tool_validation.py:1-8`）。tsm-agt 没有"这次真的发出去什么"的记录，所以多轮必然漂移。
3. **"不知道如何完成闭环"的根因形态**：Hermes 的闭环**不靠判据体系**——机器可判定的只有 gate 的退出码，判官只要一个 verdict + 一句理由，状态只有 4 个值，失败解释集中在一张前缀表（03/04 册）。tsm-agt 有 5 套并行词汇表（`TaskState` 20 值 / `CompletionReadinessAction` / `AcceptanceStatus` / `CoverageStatus` / recovery actions），彼此没有单一权威。
4. **"每次要改都是大改"的根因形态**：Hermes 用 **facade + siblings + 尺寸阈值 + 禁止 if/elif ≥4 + 禁止 re-export shim** 把"改动半径"制度化了（`AGENTS.md:232-261`）。这是**可移植性最高的一条**：它不依赖任何 Hermes 领域概念。
5. **"输出越像人话越可疑"**：Hermes 的成功侧证据是**工具副作用**（`effect_disposition`）与 gate 退出码；tsm-agt 的 38% 成功任务是**零工具调用**、契约由模型自己写、判官引用模型自己的答案（自证）。
6. **两条不变量可直接移植**：①"缓存前缀逐字节稳定"等价于"已确定的上下文不可变"；②"窄腰 + 能力在边缘"等价于"核心只留协议，能力靠注册"。
7. **接口纪律可直接移植**：`dispatch` **从不抛异常**、未知工具/异常都变成结构化错误返回（`registry.py:893-921`）；每个 `tool_call` 必有配对 result、错误也走 tool-role（`turn_tool_validation.py`）。tsm-agt 的 `INVALID_PARAM` 类错误应当是同一种"结构化返回"，而不是异常。
